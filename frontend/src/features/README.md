# features

사용자 관점의 **기능 단위**로 코드를 묶습니다. 게시판은 `board`, 실시간 채팅은 `chat`입니다. 새 기능도 가능하면 같은 방식으로 독립 폴더를 만들어 확장하세요.

## 기본 개념: Feature-based 구조

프런트엔드 폴더 구조를 만드는 방법에는 여러 가지가 있습니다.

계층 중심으로만 나누면 다음처럼 될 수 있습니다.

```text
views/
components/
composables/
```

반면 이 프로젝트는 기능을 먼저 기준으로 둡니다.

```text
features/
├─ board/
└─ chat/
```

게시판을 수정할 때 게시판 관련 파일이 한곳에 있고 채팅을 수정할 때 채팅 관련 파일이 한곳에 있으므로 작은/중간 규모 프로젝트에서 탐색하기 쉽습니다.

## 공통 코드와 기능 코드 구분

- 게시판에서만 사용 → `features/board`
- 채팅에서만 사용 → `features/chat`
- 게시판과 채팅에서 모두 사용 → `components`, `services`, `stores`, `utils` 등 공통 영역 검토

처음부터 모든 코드를 공통화하지 말고 실제로 여러 기능에서 반복될 때 옮기는 편이 유지보수에 유리합니다.

## 언제 하위 폴더를 더 나눌까?

현재처럼 기능당 파일이 몇 개뿐이면 한 폴더에서 파일명을 보는 것이 더 빠릅니다. 파일 수가 크게 늘어 탐색이 어려워지면 그때 `components`, `composables` 같은 하위 폴더를 기능 내부에 추가하면 됩니다.
